# 阶段目标定义器

## 职责

生成阶段目标文档（如 `PHASE1_GOALS.md`、`PHASE2_GOALS.md`、`PHASE3_GOALS.md`），定义"做成什么样才算成功"。

## 何时使用

- **开始新阶段前**：在生成 `PHASE*_TASKS.md` 之前，必须先生成阶段目标文档
- **阶段验收时**：需要对照目标文档验证阶段是否完成时
- **范围调整时**：需要重新定义阶段目标和非目标时

## 输入信息

调用此 skill 时，需要提供以下信息：

1. **阶段编号**：Phase 1 / Phase 2 / Phase 3 / ...

2. **依赖文档**
   - `SYSTEM_SPEC.md`（必须）
   - 上一阶段的 `PHASE*_GOALS.md`（如果有）

3. **阶段目标**
   - 本阶段要达成什么目标
   - 至少应满足哪些闭环

4. **阶段非目标**
   - 明确不做哪些内容
   - 避免范围蔓延

5. **阶段验收项**
   - G1, G2, G3, ... 每个验收项的目标和通过标准

6. **总体验收标准**
   - 阶段完成时应至少满足的条件

## 输出文档

生成 `docs/PHASE*_GOALS.md`（所有阶段），包含以下章节：

```markdown
# <项目名称> - 第<阶段>阶段目标定义（PHASE*_GOALS.md）

## 文档定位
## 第<阶段>阶段目标
## 第<阶段>阶段非目标
## 阶段验收项
### G1 <验收项名称>
### G2 <验收项名称>
...
## 总体验收标准
## AI 使用说明
```

## 关键约束

1. **文档定位**：明确说明本文档的作用和与其他文档的关系

2. **目标 vs 非目标**：
   - 目标：明确"做成什么样才算成功"
   - 非目标：明确"不做哪些内容"，避免范围蔓延

3. **验收项**：
   - 每个验收项要有明确的目标和通过标准
   - 通过标准应该是可验证的

4. **引用关系**：
   - 必须引用 `SYSTEM_SPEC.md` 的技术栈、架构约束
   - 必须引用 `SYSTEM_SPEC.md` 第9章的分期路线图

## 示例模板

参考已完成项目的阶段目标文档作为模板。

## 验收标准

- [ ] 文档包含所有必需章节
- [ ] 目标和非目标清晰明确
- [ ] 每个验收项都有可验证的通过标准
- [ ] 总体验收标准覆盖阶段核心价值
- [ ] 文档定位说明与其他文档的关系
